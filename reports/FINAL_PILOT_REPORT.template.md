## 1. Abstract and motivation
Small language-model agents must decide *what to search for, whether to search again, and when to stop*. Reinforcement learning with verifiable rewards (GRPO) is a natural way to train such decisions, but GRPO only reinforces behaviour that appears in sampled rollouts. We build a controlled search environment (BM25 over a synthetic corpus, at most two searches, exact-match reward) around Qwen3-0.6B with a LoRA adapter and ask under which conditions GRPO actually improves multi-step tool use. The study separates five things that are usually confounded: supervised initialisation, additional GRPO training, harder training data, answer-format/prompt changes, and reward shaping. Section 17 states the conclusion; Sections 10-12 give the evidence.

## 2. Research questions
1. Can GRPO alone (from the pretrained model) discover the second search needed for two-hop questions?
2. Does a small supervised warm-start (SFT) supply the missing behaviour?
3. Starting from the **same frozen SFT checkpoint (M2)**, does additional GRPO improve held-out accuracy and, if so, through better search decisions or only better answer extraction?
4. Does a richer reward (evidence-aware, grounded) beat the plain correctness reward, or is the simplest reward enough?
5. Which failures remain (reverse two-hop, unanswerable questions) and what do the tool traces show about them?

## 3. Agent architecture
```
question --> Qwen3-0.6B + LoRA --> search(query) tool call --> BM25 top-2 records --> (repeat, at most 2 searches)
                                \-> <answer>...</answer>  --> exact-match verifier --> reward
```
The policy is Qwen3-0.6B in non-thinking mode with its native `<tool_call>` format. The only tool is `search(query)`; the retriever is deterministic BM25 (lowercasing, stop-word removal, light stemming) over the split's own corpus. A reminder appended to each tool output tells the model what kind of value to answer with (`typed`), and, for the hard benchmark, that it may answer `insufficient evidence` (`typed_abstain`). Gold labels and evidence ids are never visible to the model.

## 4. MDP formulation
* **State/observation:** question plus history (queries and retrieved records). The simulator's hidden state (which gold documents were held) is *not* shown to the policy.
* **Actions:** `search(query)` or a final answer in `<answer>...</answer>`; further searches beyond 2 are invalid actions.
* **Transition:** deterministic BM25 lookup; the history grows by the query and the two records.
* **Horizon:** at most 2 searches then an answer.
* **Reward (original):** `R = 1.0 * correct - 0.05 * N_search - 0.10 * N_invalid`.
* **Oracle baseline:** a finite-horizon Bellman baseline over the privileged state {none, partial, complete evidence}. It is an oracle reference, not a fair competitor.

## 5. Models and training stack
Qwen3-0.6B; LoRA r=8, alpha=16, on `q_proj`/`v_proj` (1,146,880 trainable parameters); Hugging Face TRL 1.17 `GRPOTrainer` with `environment_factory` (one environment per rollout, tool tokens masked from the loss), group size 4 (or as selected by the signal probe), 100 steps for the hard-benchmark runs, learning rate 2e-5, temperature 0.7 (or the probe-selected value), `beta = 0` (no reference model, hence no KL metric). **SFT:** 200 correct trajectories built from `train` and `twohop_train`, loss on the model's own turns only. **BM25:** `rank-bm25`, top-2.

GRPO advantage: for a group of G rollouts of one prompt, `A_i = (r_i - mean) / (std + 1e-4)`. If all rewards in a group are equal, every advantage and the loss are exactly zero, so that group contributes **no gradient**; a bonus that is identical across a group cancels. This is why we log the share of groups with non-zero reward spread throughout.

## 6. Training environment and dataset creation
* **Original data:** synthetic fictional projects/people with lookup, no-search and two-hop (project -> investigator -> affiliation) questions; separate train/dev/test(and sealed `final`, `twohop_final`) splits with disjoint entities and corpora; leakage tests in `tests/`.
* **Hard benchmark** (`data/make_hard.py`, seed 20261106, hash-locked in `data/manifest_hard.json`): `hard_train` (120 tasks), `hard_dev` (60), `hard_final` (120, locked) over six categories: `standard`, `distractor_name` (a decoy "Project N Prime"), `distractor_person` (shared surname), `stale_affiliation` (a "previous affiliation" record that outranks the right one), `reverse_two_hop` (person first, project second), `unanswerable` (a required record is missing; the correct answer is `insufficient evidence`). A scripted oracle that reads only observed text solves all 300 tasks, and a naive "trust the top record" reader scores 0/10 on `stale_affiliation` and 10/10 on the other dev categories, so the benchmark is solvable and only partly adversarial. The generator was run once more (revision 2) *before any model saw the data*, because the first stale-affiliation records did not actually mislead; the manifest records this.

## 7. Reward functions
* **M3 original:** the reward above.
* **M4 evidence-aware:** `R + 0.10 * first_evidence + 0.30 * complete_chain`, using gold doc ids *inside the verifier only*.
* **M4g grounded:** original reward minus 0.25 for a non-abstaining answer that appears neither in the question nor in any retrieved record; no gold ids.
* Earlier RL-only variants (potential-difference shaping, explicit exploration incentive `gamma`) are described in Section 12.

## 8. Experimental methodology
* **Matched comparisons.** M3/M4/M4g start from the **same frozen M2 checkpoint** (`outputs/study_sft/B/adapter`), use the same data, steps, learning rate and seeds, and differ only in `reward.mode`.
* **M1** = the original GRPO model without SFT (condition A); **M2** = SFT only; **M3/M4/M4g** = SFT + GRPO. M1 never saw the `typed_abstain` reminder, so it is shown but not used to rank the GRPO variants.
* **Gates before spending compute:** a headroom gate (is M2 already near ceiling on `hard_dev`?) and a signal gate (do enough GRPO groups have reward spread?). Both are saved as JSON decisions.
* **Freeze before the sealed test.** The headline model was selected on development splits only, by a rule declared in `src/freeze_hard.py`, and recorded in an immutable manifest before `hard_final` was evaluated (Section 10.1).
* **Statistics.** Accuracy is reported as k/n with 95% Wilson intervals; paired comparisons use the exact sign (McNemar) test on discordant tasks and a paired bootstrap interval of the accuracy difference. Per-category n is 10 (dev) or 20 (final), so category-level differences are suggestive only.
* **Format control.** The same M2 checkpoint is evaluated under both reminders (`typed`, the one it was trained with, and `typed_abstain`), to separate a reminder effect from a training effect.
* **Decoding.** Greedy for all headline numbers; sampled decoding only where stated.

## 9. Training curves
{{inc:figures_block.md}}

**How to read the loss.** GRPO's policy loss is `-(clipped ratio x group-normalised advantage)`, averaged over tokens. It is approximately zero at the first gradient step by construction, can be positive or negative, and is exactly zero on every step where all rollouts of a group tie. A near-zero loss therefore says nothing about convergence, and the curves must be read with reward, the share of groups with non-zero reward spread, and behaviour metrics. Smoothed lines are labelled moving averages over the raw per-step values. Training reward is measured on prompts the model trains on and is not evidence of generalisation.

### 10.6 Search decisions or answer extraction?
Accuracy factorises as `P(correct) = P(complete evidence chain) x P(correct | chain)`. The behaviour tables above report both factors, the second-search rate, premature stops, unparseable answers and invalid calls. A gain concentrated in `P(chain)` is a change in search behaviour; a gain in `P(correct | chain)` or in the parseable-answer rate is answer production or formatting. The format-control rows show how much of any difference is explained by the reminder alone. This is an observable-behaviour analysis; it does not establish what the model "reasoned" internally.

## 11. RL-only exploration experiments (no SFT)
Established facts from the base model [local]: two scripted BM25 queries retrieve both documents of a two-hop task 100% of the time; the base model sampled a second search 0/80 (T=0.7) and 0/80 (T=1.0) times; the original GRPO model (condition A) stopped after one search on 30/30 two-hop dev tasks and answered with the investigator's name in 77% of them [Colab, pasted]. With the second search forced, the base model scores 10/30 under the default reminder and 26/30 under the typed reminder [local]. Hence retrieval and tool syntax are not the bottleneck: the missing behaviour is a never-sampled action, which GRPO cannot reinforce because no reward difference exists inside a group.

The staged RL-only experiments F0-F4 (higher temperature / larger group, evidence shaping, potential shaping, explicit exploration incentive, two-hop-only curriculum) are implemented in `run_rl_only_study.sh`. {{inc:tables/rl_only_status.md}}

**We do not claim that GRPO alone discovered two-hop exploration.**

## 14. Ablation analysis
* Reward variants (M3 vs M4 vs M4g) from the same M2 checkpoint, same seeds: tables in 10.3-10.5 and the per-seed figure. The variants usually differ by one or two questions; we therefore select the **simplest competitive** reward, not the nominal winner.
* Reminder (`typed` vs `typed_abstain`) on the same checkpoint: format control in 10.5.
* Data: GRPO runs train on `hard_train` + original one-hop tasks, M2 does not. There is **no SFT-on-`hard_train` control**, so a gain shows that "GRPO on this task distribution helps this checkpoint", not that RL beats SFT given equal data. Building that control is the most valuable follow-up.

## 16. Limitations and threats to validity
* Small model (0.6B), synthetic corpora, fixed question templates, BM25 with a small corpus, at most two searches (three-hop and re-query-after-failure are not covered).
* Few tasks: 60 `hard_dev`, 120 `hard_final`, 10-20 per category; a 30/30 result has a 95% Wilson lower bound of 88.6%.
* Two training seeds per variant; seeds are not independent samples of the "true" method effect.
* Reminder confound (`typed_abstain` vs `typed`) and training-data confound (hard_train) discussed in Sections 10.5 and 14; no SFT-on-hard control.
* Gold evidence ids are used as privileged reward information in M4 (never shown to the policy); M4g uses none.
* M1 was not trained or evaluated with the abstention reminder.
* Sealed-set hygiene: `hard_final` was evaluated once after the freeze; any earlier view of the older `final`/`twohop_final` sealed splits is recorded in the manifest and those splits are not untouched if they were viewed.
* Compute is limited to free Colab (L4); heavy training was never run on the author's Mac.
